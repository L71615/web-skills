# 制作与验收

只在实施、改版或最终检查时读取。按风险裁剪，不把清单当作所有项目的必填项。

## 开始前

- 已有项目：读取运行说明、包脚本、路由、样式、素材、依赖和未提交变更。建立当前可运行基线，保留用户改动。
- 新项目：先确认页面与功能范围、内容来源、技术与部署约束。静态展示可以简单；需要共享数据、身份、支付或私密 API 时安排相应服务能力。
- 对成本高或存在不确定性的依赖先做最小验证，如文件大小、支付沙箱、登录回调或托管运行方式。

## 实施节奏

先完成代表性页面的结构、真实长度内容和响应式布局，再完成交互状态与数据链路。抽取真正重复的组件和语义变量。每个可见增量后运行相关检查并看实际渲染；重要改动保留可恢复点。局部调整无需重新做整站规划。

## 验收矩阵

选择关键页面和流程，在适用的窄手机、平板或窄容器、桌面上检查：

1. 首屏、长内容、章节转场和页脚；横向溢出、遮挡、断行、资源空白及布局跳动。
2. 导航、链接、按钮、直接访问内页和刷新；目标地址与返回路径。
3. 表单的有效、无效、加载、成功、失败与重试；权限和数据持久化按实际要求验证。
4. 键盘顺序、可见焦点、语义标签、触控目标、对比度、缩放和减少动画。
5. 浏览器控制台与网络错误、构建结果、图片和字体加载、移动端成本。
6. 公开页面的标题和描述、索引规则、规范 URL、站点地图或结构化数据，仅在项目需要时检查。
7. 部署后用真实公网地址复查 HTTPS、路由、资源、主要操作和生产配置；本地预览不能替代这一步。

遇到响应式缺陷先查容器、Grid/Flex 约束、最小宽度、换行、固定定位和媒体尺寸。优先修复布局根因，并在相邻宽度及长内容状态复查。记录测试条件、结果、未覆盖项与后续责任。
