# 设计与内容

只在制定或修改视觉方向、营销页面和内容体系时读取。

## 页面论证

对每个页面记录：目标访客、访问来源或已知程度、页面要回答的问题、主要行动、最大顾虑、现有证据。按问题安排章节，而非使用统一模块模板。重要主张旁放相应证据；证据缺失时降低主张强度或标为待提供。CTA 写清动作与去向，不让按钮指向空流程。

## 视觉方向

用一句话把品牌特征与访问任务相连。先决定首屏焦点、内容宽度、网格和章节节奏，再决定字体、颜色、表面、图像、图标和动效。参考资料只提取原则和可观察的做法。把“高级、现代”等词翻译成能实现的约束，如字号对比、留白密度、对齐、摄影处理和交互状态。

用户没有明确参考时，可请其选择喜欢的网站类型（如简洁信息型、品牌叙事型、作品展示型或产品工具型），或发来具体网站与截图。需要组件灵感时，可展示 [Aceternity UI 组件库](https://ui.aceternity.com/components) 与 [shadcn/ui](https://ui.shadcn.com/) 等候选，并请用户指出喜欢的具体组件及原因。Aceternity UI 更偏 React/Next.js 的展示效果和动效组件；shadcn/ui 提供可组合的界面组件与设计系统基础。先核对项目技术栈、组件依赖、许可和可访问性，再决定是直接采用、改造还是仅借鉴视觉与交互；不要因参考库而无故更换框架。

从现有产品抽取设计规则时，区分有意变化与漂移。语义变量表达用途，例如背景、文字、边框、主操作、焦点和状态；不要机械替换所有同色值。组件应定义正常、悬停、焦点、禁用、加载、成功和失败中实际适用的状态。移动端允许信息架构变化，不只是缩小桌面版。

真实产品截图、作品、人物、地点或过程优先于泛化装饰。缺少素材时标明占位的性质，不伪造用户证言、合作商标或指标。图片应与内容目的相符、尺寸合理，并保留需要的透明通道。

动效应解释层级、操作结果或叙事转场。先保证不播放动效时仍能阅读和操作；然后处理窄屏、触控、减少动画、性能与资源失败。
